Расхождения модели с замером (§6.4)

PP decode не сериализован в core → завышение tg на +75%. Модель PP-2 @S=131K f16: 58,09 t/s против замеренного C-18 = 33.19 (CUDA). Core предполагает параллельное чтение слоёв стадиями; при batch=1 цепь между картами сериализована — замер PP/SG CUDA = 0.87 согласуется с сериализацией, а не с моделью.
TS prefill: завышение в 3,2× @S=131K f16. Модель TS-2 = 1 547,71 t/s против замеренного ~489 (Vulkan). При этом SG модель ≈ 802,85 vs замер ~800 — т.е. core предсказывает ускорение TS в ~1,9×, а реальность: TS медленнее SG на ~105 с (268 vs 164 с). Штраф синхронизации split-GEMM по consumer PCIe не входит в core; их член allreduce [S,h] добавляет лишь ~3 с.
Mirror-KV поправка: f16 — ошибка +5% @131K, q8_0 — всё ещё +38…+42%. После поправки TS tg f16 = 16,26 t/s против замеренного 15.52 (E3 v3) — близко. Для q8_0 модель считает квантование KV чистым выигрышем байт, но Vulkan платит цену dequant (C-12/C-15/C-19): замер q8/f16 = 0.82–0.94 против модели +16…+40%.
Термин весов int4 core = 6.0 GB vs Q4_K_M фактически 6,734 GB (+12%). Ошибка SG tg модели по сетке: +11% @S=1K … -16% @S=262K (f16). Часть ошибки компенсируется тем, что implied BW Vulkan неконстантен: tg почти плоский от S=1K до 131K при +30% байт/токен — эффективная пропускная способность шины растёт с длиной KV-чтения (C-21).
Prefill калиброван по Vulkan; сверка с CUDA-якорями. SG model = 802,85 t/s @S=131K — совпадает с Vulkan-замером (~800). SG-CUDA (C-13) на треть выше кривой: 1053.55 против 802,85 (mfu CUDA ≈ 0.46 против AOI_CAL.mfuPrefill = 0.35). PP-CUDA (C-18) неожиданно ложится почти точно на Vulkan-калиброванную модель: @131K 1 605,39 vs 1713.81 (-6%), @262K 1 138,23 vs 1133.46 (+0%) — совпадение смещения mfu и P2P-члена.

Главный вывод блока 6

На consumer PCIe при batch=1 мульти-GPU не выигрывает ни в PP, ни в TS: decode TS-2 хуже SG во всех клетках (0.38–0.49×), PP-2 сериализует цепь слоёв и даёт ~−4…−7% overhead. Польза двух карт = экономия VRAM (KV распределяется по картам: 5.68→7.83 GB/карту TS mirror-KV против 10.6 GB SG @262K f16) + ускорение compute-bound prefill: ×1.63–1.65 PP-CUDA (C-18), ×5.4 TS-Vulkan @S=1K (гейт†). Расчётная модель core корректна по архитектуре, но требует трёх поправок для consumer-стека: сериализация PP decode, штраф split-GEMM sync в prefill и mirror-KV геометрия gemma-4.
