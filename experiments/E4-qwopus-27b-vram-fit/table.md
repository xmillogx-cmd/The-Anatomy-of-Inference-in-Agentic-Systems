# E4 — Qwopus3.8-27B-Coder-Flash на 2× RTX 5060 Ti 16 GB: влезает/не влезает

Модель: `Jackrong_Qwopus3.8-27B-Coder-Flash-Q4_K_M.gguf` = **17,442,401,824 B ≈ 16.2 GiB** — больше одной карты (16 GB) ещё до KV. arch=qwen35, hybrid: 65 блоков, full-attn только в 17 из них (interval 4), kv_heads=4, head_dim=256 → KV f16 ≈ **69,632 B/pos** суммарно по всем слоям; recurrent-слои держат фиксированное SSM-состояние. Нативный контекст 262144.

Раннер: runner-cuda (llama.cpp b11819 + mirror-KV патч), `-n 64 --ignore-eos`, промпты E3 (`prompt_512/131072/262144.txt`). Прогоны: основной `run_e4.bat` (12.11.2026 5:24–6:05), дополнение q4 `run_e4_q4.bat` (12.11.2026 12:49). Все точки exit=0 — см. находку «exit=0-ловушка» ниже.

## 3. exit=0-ловушка (главная методологическая находка)

Строка 1 завершилась кодом 0 при фактическом OOM: build runner-cuda включает auto-fit (`common_fit_params`), и вместо жёсткого падения на «модель не влезла» llama.cpp **тихо переносит часть весов/KV в RAM** и продолжает работу. Симптом — только tg (7.71 против 22.14). Вывод: при проверке «влезает/не влезает» exit code ненадежен, смотреть надо offload-долю (`llama_model_memory_usage`) или замерять tg/pp против ожидаемого базлайна.
