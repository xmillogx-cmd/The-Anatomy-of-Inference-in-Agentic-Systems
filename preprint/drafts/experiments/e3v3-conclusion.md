# E3 v3 — вывод: TS (tensor parallelism) на двух RTX 5060 Ti, gemma-4 Q4_K_M

**Статус:** сетка 12/12 exit=0 (запуск пользователя, 2026-11-11 ~19:35), run_log.txt без ABORT.
Новый вывод проекта — **C-21** в `CONCLUSIONS.md`.

## Что проверялось

TS mode (`-sm tensor -ts 1,1`) впервые стал исполняемым на gemma-4 после локальной сборки TDM-GCC/Vulkan с патчем mirror-KV (`src/llama-model.cpp` L542–L563: глобальные слои с `n_head_kv < n_devices` получают attn_k + KV **зеркально** вместо axis-0 split — assert C-17 снят). Эквивалентность гейта (S=1024 f16, SG vs TS): идентичный префикс до `<|channel>thought`, связные продолжения; строгое A==B недостижимо для split-GEMM (порядок сложения через allreduce).

## Выводы

1. **TS batch=1 на consumer PCIe хуже SG во всех клетках decode** (tg TS/SG = 0.38–0.49). Overhead TS−SG = +35.7/+48.8 ms/token @131k, +37.6/+41.9 ms/token @262k ≈ **0.37–0.51 ms на каждый из 96 allreduces/token** (L·2 = 48·2). Согласуется с литературой:
   - **SNU ThunderEP** (2609.40093) — ровно наша топология: consumer PCIe без P2P, весь трафик через host memory; одновременная работа двух GPU даёт ~35.5 GB/s/GPU — порядок величины перекрытия коммуникации и вычислений у них на порядок ниже нашего overhead-лимита.
   - **Dell trade-off** (2610.05305): `T_comm^TP = k(P−1)[α + |M|/(P·β)]` — при P=2, batch=1 коммуникационный член не размазывается по батчу; TP comm = 30–40% decode latency при малом batch.
   - **Megatron-LM** (1909.08053): «careful attention to the placement of layer normalization ... is critical» — структурный принцип, реализованный в mirror-KV патче: нормализация и глобальный KV не могут расщепляться по картам без синхронизации на каждый слой.
2. **BW-потолок mirror-KV недостижим**: байты/карту 5.682 / 4.524 / 7.830 / 5.598 GB → потолок @BW_vulkan = 43.57 / 54.72 / 31.62 / 44.23 t/s против замеренных (efficiency **23–43%**). Доминирует синхронизация, а не пропускная способность — предсказания docstring inference_math.py ≈70.0/50.8 @BW_cuda=397.7 опровергнуты Vulkan-замером и по BW, и по sync-overhead.
3. **q8_0 KV без ожидаемого выигрыша** во всех клетках: замеренные tg q8/f16 = 0.97/1.00 (SG), 0.82/0.94 (TS) против модельных +25.6%/+39.9% в mirror-режиме — расширение C-12/C-15/C-19 на Vulkan+TS.
4. **prefill: TS быстрее SG только в малом контексте** (@S=1024: 5.4× — split-GEMM параллелит compute-bound фазу), на длинном TS pp = 0.61–0.74× SG (сериализация allreduce).
5. **Противопоставление C-18 (PP-CUDA)**: PP tg 33.19/26.89 @131k/262k f16 — выше даже TS-Vulkan 15.52/13.51; **на consumer PCIe при batch=1 мульти-GPU не выигрывает ни в PP, ни в TS** — польза = экономия VRAM + ускорение compute-bound prefill (×1.63–1.65 PP-CUDA, ×5.4 TS-Vulkan @S=1024).
6. **Калибровка BW_eff Vulkan = 247.6 GB/s** (якорь гейта tg 34.94 × 7,085,873,116 B/token) — ×0.553 spec 448 GB/s; простой BW-модель не описывает Vulkan по всему S (implied BW SG: 247–321 GB/s).
