# E3 v2 — вывод: истинный мульти-GPU layer split (PP) на двух RTX 5060 Ti, S=131k/256k

Замер 24.10.2026 (обе карты, `-sm layer`, 6/6 exit=0, префлохты A–D OK). Raw в `raw/`, таблица в `table.md`. TS (`-sm tensor`) исключён из сетки — детерминированный краш при построении графа на gemma-4 hybrid SWA (C-17), сам краш = отрицательный результат блока 6.

## Вердикты по гипотезам config.json

1. **PP prefill до ~1.8–2× single-GPU минус bubble → подтверждено частично: ×1.63–1.65.** Отношение стабильно на обоих S и в обоих KV-квантах (f16 1713.81/1053.55 = **×1.627** @131k, 1133.46/686.94 = **×1.650** @262k; q8_0 ×1.631 / ×1.635). Механизм: prefill батчится (n_batch=2048) — пайплайн скрывает сериализацию цепочки слоёв между картами, КПД ~76–79% от идеала 2× (эффективные TFLOPS f16: ≈68.0 @131k, ≈64.5 @262k против 41.8/39.1 single-GPU — C-13).
2. **tg decode ~0.9–1.0× → подтверждено как «выигрыша нет».** batch=1: цепь слоёв между картами сериализована, оверлепа нет. Сырые отношения к bench E2: 0.871/0.848 (f16), 0.898/0.897 (q8_0). С поправкой на runner-gap CLI-vs-bench ≈ −9% (якорь префлохта D: tg@1k = **43.06** против bench d1k ≈ **47.4**) реальный overhead PP в decode ≈ **−4…−7%** (f16, растёт с S) и ~−1% (q8_0). Вывод: на этом стеке PP в decode batch=1 не даёт выигрыша — его польза = экономия VRAM (~2 GiB KV/карту @256k вместо 4).
3. **q8_0 KV перекроется ли на ≥131k → нет.** tg q8_0/f16 = 25.58/33.19 = **0.771** @131k и 18.03/26.89 = **0.671** @262k; pp overhead −1.8…−2.9% (C-14 подтверждается в мульти-GPU). Dequant-overhead не окупается даже на длинном контексте и при сплите KV по картам — расширение C-12/C-15, зафиксировано как **C-19**.
4. **TS unusable → подтверждено** (C-17): отрицательный результат блока 6, краш задокументирован с assert и механизмом (ggml-backend-meta.cpp:547, per-row ops + axis-0 split).

## Итог для блока 6 статьи

На двух consumer-картах в llama.cpp b11819: **PP (`-sm layer`) — единственный рабочий режим истинного мульти-GPU**; выигрыш только в compute-bound префилле/больших batch (×1.63–1.65), decode batch=1 остаётся сериализованным (нет оверлепа, −4…−7%). **TS (`-sm tensor`) детерминированно сломан** на гибридной SWA-архитектуре gemma-4 по дизайну upstream. Практический вывод для агентских long-context систем: две карты окупаются там, где workload содержит длинные prefill (RAG/агентский контекст 128–256k), но не ускоряют стриминг decode.
